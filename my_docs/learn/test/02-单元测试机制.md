# Filament 单元测试机制

## 单元测试架构

Filament 的单元测试基于 Google Test 框架，采用模块化设计，每个库都有独立的测试套件。

## 测试框架配置

### Google Test 集成
**位置**: `third_party/libgtest/tnt/`
**版本**: 自定义构建的 gtest 版本

**CMakeLists.txt 集成**:
```cmake
# 主 CMakeLists.txt
add_subdirectory(${EXTERNAL}/libgtest/tnt)

# 各模块测试配置
target_link_libraries(test_${TARGET} PRIVATE gtest)
```

### 测试可执行文件命名规范
- 命名格式: `test_${MODULE_NAME}`
- 输出目录: `out/cmake-debug/`
- 报告格式: XML (sponge_log.xml)

## 核心模块测试详解

### 1. 数学库测试 (libs/math)

**测试文件**: `libs/math/tests/`
- `test_fast.cpp` - 快速数学函数
- `test_half.cpp` - 半精度浮点数
- `test_mat.cpp` - 矩阵运算
- `test_quat.cpp` - 四元数
- `test_vec.cpp` - 向量运算

**示例测试用例**:
```cpp
// libs/math/tests/test_vec.cpp
TEST(VecTest, CrossProduct) {
    float3 a(1, 0, 0);
    float3 b(0, 1, 0);
    float3 c = cross(a, b);
    EXPECT_FLOAT_EQ(c.x, 0.0f);
    EXPECT_FLOAT_EQ(c.y, 0.0f);
    EXPECT_FLOAT_EQ(c.z, 1.0f);
}
```

### 2. 工具库测试 (libs/utils)

**测试文件**: `libs/utils/test/`
- `test_Allocators.cpp` - 内存分配器
- `test_JobSystem.cpp` - 作业系统
- `test_Entity.cpp` - 实体管理
- `test_Hash.cpp` - 哈希函数
- 等等...

**测试入口**: `test_utils_main.cpp`
```cpp
#include <gtest/gtest.h>

int main(int argc, char** argv) {
    ::testing::InitGoogleTest(&argc, argv);
    return RUN_ALL_TESTS();
}
```

**关键测试用例**:
```cpp
// 测试作业系统
TEST(JobSystem, BasicFunctionality) {
    JobSystem js;
    js.adopt();

    std::atomic<int> counter{0};
    auto* job = js.create(nullptr, [&counter]() {
        counter.fetch_add(1);
    });

    js.run(job);
    js.waitAndRelease(job);

    EXPECT_EQ(counter.load(), 1);
}
```

## 测试运行配置

### CMake 测试目标生成

每个模块的测试都通过 CMake 自动配置：

```cmake
# 示例：libs/utils/CMakeLists.txt
if (NOT ANDROID AND NOT WEBGL AND NOT IOS)
    set(TEST_SRCS
        test/test_Allocators.cpp
        test/test_BinaryTreeArray.cpp
        test/test_Entity.cpp
        # ... 更多测试文件
        test/test_utils_main.cpp
    )

    add_executable(test_${TARGET} ${TEST_SRCS})

    target_link_libraries(test_${TARGET} PRIVATE
        ${TARGET}
        gtest
        # 平台特定依赖...
    )
endif()
```

### 平台特定配置

**条件编译**:
- `NOT ANDROID` - 桌面平台测试
- `NOT WEBGL` - 非 WebGL 环境
- `NOT IOS` - 非 iOS 平台

**平台依赖**:
```cmake
if (LINUX)
    target_link_libraries(test_utils PRIVATE Threads::Threads dl)
endif()

if (APPLE)
    target_link_libraries(test_utils PRIVATE "-framework Foundation")
endif()
```

## 测试执行流程

### 1. 构建测试
```bash
# 触发测试构建
./build.sh debug

# 或者只构建特定测试
cmake --build out/cmake-debug --target test_math
```

### 2. 执行测试
```bash
# 通过 build.sh 运行所有测试
./build.sh test

# 或者直接运行特定测试
./out/cmake-debug/libs/math/test_math
```

### 3. 测试过滤

使用 gtest 过滤器运行特定测试：
```bash
# 运行特定测试用例
./out/cmake-debug/filament/test/test_filament \
    --gtest_filter="FilamentTest.AabbMath"

# 排除某些测试
./out/cmake-debug/filament/test/test_filament \
    --gtest_filter="-FilamentTest.FroxelData"
```

## 测试报告生成

### XML 输出格式
每个测试都配置为生成 XML 报告：
```bash
./out/cmake-debug/test_name \
    --gtest_output="xml:out/test-results/test_name/sponge_log.xml"
```

### 报告结构
```xml

<testsuites tests="5" failures="0" disabled="0" errors="0" time="0.002">
  <testsuite name="MathTest" tests="3" failures="0" disabled="0" errors="0" time="0.001">

    <testcase name="MatrixMultiply" classname="MathTest" time="0.001"/>
  </testsuite>
</testsuites>
```

## 测试最佳实践

### 1. 测试命名规范
```cpp
// 模块_功能_预期结果
TEST(Math, VectorAddition_ValidInputs_CorrectSum)
TEST(Utils, JobSystem_CreateAndRun_ExecutesCorrectly)
```

### 2. 断言选择
```cpp
// 浮点数比较
EXPECT_FLOAT_EQ(actual, expected);
EXPECT_NEAR(actual, expected, tolerance);

// 自定义谓词
EXPECT_PRED2(vec3eq, result.min, expected.min);

// 布尔检查
EXPECT_TRUE(condition);
EXPECT_FALSE(condition);
```

### 3. 测试数据管理
```cpp
// 使用测试夹具
class MathTest : public ::testing::Test {
protected:
    void SetUp() override {
        // 初始化测试数据
    }

    float3 testVector{1.0f, 2.0f, 3.0f};
};

TEST_F(MathTest, VectorNormalization) {
    // 使用 testVector
}
```

### 4. 错误处理测试
```cpp
TEST(Allocator, OutOfMemory_ThrowsException) {
    EXPECT_THROW({
        // 触发内存不足的操作
    }, std::bad_alloc);
}
```

## 常见问题和解决方案

### 1. 链接错误
**问题**: 找不到测试依赖
**解决**: 检查 CMakeLists.txt 中的 `target_link_libraries`

### 2. 平台特定测试失败
**问题**: 某些测试只在特定平台工作
**解决**: 使用条件编译和平台检查

### 3. 浮点数精度问题
**问题**: 浮点数比较失败
**解决**: 使用 `EXPECT_NEAR` 而不是 `EXPECT_EQ`

这个单元测试机制确保了 Filament 各个模块的功能正确性和稳定性。
