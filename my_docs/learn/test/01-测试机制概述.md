# Filament 测试机制概述

## 测试架构设计

Filament 采用分层的测试架构，确保代码质量和功能正确性：

```
┌─────────────────┐
│   集成测试      │  渲染管线端到端测试
├─────────────────┤
│   渲染差异测试  │  图像对比验证
├─────────────────┤
│   后端测试      │  图形API兼容性
├─────────────────┤
│   单元测试      │  模块功能验证
└─────────────────┘
```

## 测试框架技术栈

### 核心测试框架
- **Google Test (gtest)**: 主要的单元测试框架
- **CMake**: 构建系统集成，自动发现和配置测试
- **Mesa**: 软件渲染，支持无头环境测试
- **Python**: 测试脚本和自动化工具

### 测试类型分类

#### 1. 单元测试 (Unit Tests)
**目的**: 验证各个模块的核心功能
**框架**: Google Test
**位置**: `libs/*/test/`, `filament/test/`

涵盖的模块：
- `libs/math` - 数学库测试
- `libs/utils` - 工具库测试
- `libs/filamat` - 材质编译器测试
- `filament/test` - 引擎核心测试

#### 2. 后端测试 (Backend Tests)
**目的**: 验证图形API后端的正确性
**位置**: `filament/backend/test/`
**支持**: OpenGL, Vulkan, Metal, WebGPU

关键测试用例：
- 缓冲区管理
- 纹理操作
- 着色器编译
- 渲染状态

#### 3. 渲染差异测试 (Render Diff Tests)
**目的**: 通过图像对比验证渲染结果
**位置**: `test/renderdiff/`
**技术**: Mesa软件渲染 + 图像对比

#### 4. 工具测试 (Tool Tests)
**目的**: 验证构建工具和辅助工具
**涵盖**: matc, cmgen, filamesh 等工具

## CMake 测试集成

### 测试目标命名规范
```cmake
# 为库创建测试可执行文件
add_executable(test_${TARGET} tests/test_${TARGET}.cpp)

# 链接测试依赖
target_link_libraries(test_${TARGET} PRIVATE ${TARGET} gtest)
```

### 测试发现机制
每个模块的 CMakeLists.txt 都包含测试配置：

```cmake
# 示例：libs/math/CMakeLists.txt
if (NOT ANDROID AND NOT WEBGL AND NOT IOS)
    add_executable(test_math
        tests/test_fast.cpp
        tests/test_half.cpp
        tests/test_mat.cpp
        tests/test_quat.cpp
        tests/test_vec.cpp
    )
    target_link_libraries(test_math PRIVATE math gtest)
endif()
```

## 测试数据管理

### 测试资产
- **glTF 模型**: 从 `filament-assets` 仓库获取
- **参考图像**: 用于渲染差异对比的黄金标准
- **着色器**: 测试用的 GLSL/MSL 代码

### 版本控制策略
- 测试代码: 主仓库
- 大型资产: 单独的 `filament-assets` 仓库
- 参考图像: Git LFS 管理

## 持续集成 (CI/CD)

### GitHub Actions 工作流
**文件**: `.github/workflows/presubmit.yml`

主要测试作业：
1. **test-renderdiff**: macOS 渲染差异测试
2. **validate-docs**: 文档验证
3. **build**: 多平台构建验证

### 测试触发条件
- **Pull Request**: 所有测试
- **Push to main**: 完整测试套件
- **Nightly**: 扩展测试和性能基准

## 测试配置文件

### 测试列表配置
**文件**: `build/common/test_list.txt`

```
libs/viewer/test_settings
filament/test/test_filament --gtest_filter=-FilamentTest.FroxelData:...
filament/test/test_material_parser
libs/math/test_math
libs/image/test_image compare libs/image/tests/reference/
...
```

### 执行流程
1. `build.sh -u` 触发测试构建
2. 解析 `test_list.txt` 获取测试列表
3. 逐个执行测试，生成 XML 报告
4. 聚合结果用于 CI 状态报告

## 平台特定的测试

### macOS
- 完整的 Metal 后端测试
- 渲染差异测试（使用 Mesa）
- 所有工具测试

### Linux
- OpenGL 和 Vulkan 后端测试
- 无头渲染测试
- 命令行工具测试

### Android
- 受限的单元测试
- 设备特定的后端测试

### WebGL
- TypeScript 类型检查
- WebGL 特定的后端测试

## 测试性能和优化

### 并行执行
测试设计为可并行运行，提高 CI 效率

### 缓存策略
- 构建缓存: 避免重复编译
- 资产缓存: 复用下载的测试资产

### 选择性测试
通过 gtest 过滤器支持选择性测试执行

## 错误处理和调试

### 测试失败处理
- 详细的错误日志
- 失败图像的自动保存
- 回归测试支持

### 调试工具
- Visual Studio Code 集成
- GDB/LLDB 调试支持
- 图像差异可视化工具

这个测试机制确保了 Filament 在各种平台和配置下的稳定性和正确性。
